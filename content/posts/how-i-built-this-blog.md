# 从 0 到 1：我是如何搭建这个博客的

你现在看到的这个网站，是我从零开始写的。它没有使用任何博客平台或 CMS，而是一个标准的 Next.js 全栈项目。这篇文章记录它的技术选型和实现思路，也算是给这个站点做一个"开机自检"。

## 为什么自己搭？

现成的平台很多，但自己搭有三个无法替代的理由：

- **数据完全属于自己**。文章是仓库里的 `.md` 文件，任何平台倒闭都带不走我的字。
- **前端就是我的简历**。对一个软件工程专业的学生来说，这个站点本身就是作品——它的代码就是公开可查的。
- **写作即工程**。给博客加功能（标签、目录、RSS）的过程，本身就是对 Web 全栈开发的完整练习。

## 技术选型

核心栈很克制：**Next.js 16（App Router）+ React 19 + TypeScript + 原生 CSS（CSS Modules）**。

没有引入 Tailwind，也没有引入组件库。原因很简单：我想让每一个像素的决策都由自己完成。全站的设计语言建立在 `globals.css` 里的一组 CSS 变量上：

```css
:root {
  --accent-1: #6366f1;   /* Indigo */
  --accent-2: #8b5cf6;   /* Violet */
  --bg-card: rgba(255, 255, 255, 0.75);
  --radius-lg: 24px;
}
[data-theme='dark'] {
  --accent-1: #818cf8;
  --bg-card: rgba(17, 18, 32, 0.85);
}
```

暗色模式因此几乎是零成本的：组件只引用语义变量，`next-themes` 切换 `data-theme` 属性，所有颜色随主题整体翻转。

## Markdown 渲染管线

文章是 `content/posts/` 下的 Markdown 文件，frontmatter 记录标题、日期、摘要和标签。渲染走一条 unified 管线：

```ts
MDXRemote({
  source: content,
  options: {
    mdxOptions: {
      remarkPlugins: [remarkGfm, remarkMath],
      rehypePlugins: [rehypeKatex, rehypeHighlight, rehypeSlug],
    },
  },
});
```

这条链路让文章直接获得：GFM 表格、数学公式、代码高亮和标题锚点。比如阅读时长的估算，就基于一个简单公式：

$$
T = \left\lceil \frac{C_{zh}}{400} + \frac{W_{en}}{200} \right\rceil
$$

中文按 400 字/分钟、英文按 200 词/分钟折算。KaTeX 负责把它漂亮地排出来。

代码块的"复制"按钮是我比较得意的细节：一个客户端组件接管 `pre` 的渲染，悬停时浮现按钮，点击写入剪贴板——技术博客的高频动作值得一次点击解决。

## 目录与标签：两处容易踩坑的地方

**目录（TOC）**最初的实现是自己写正则提取 `##` 标题，但很快发现两个问题：代码块里的 `#` 注释会被误认成标题；自己算的锚点 ID 和 `rehype-slug` 生成的 ID 在中英文混排时对不上，点击目录跳不过去。

最终的解法是让目录和正文走**同一条管线**：先用相同的插件链把 Markdown 转成 HTML，再从 HTML 里提取 `h2`~`h4` 及其 `id`。锚点从此天然一致，不可能错位。

**标签**则是把双刃剑：展示容易，聚合难。每篇文章的标签都会生成对应的 `/tags/[标签名]` 聚合页（构建时静态生成），点击任何标签都能看到同主题的全部文章。

## 一些工程细节

- **草稿机制**：frontmatter 里写 `draft: true`，生产构建会完全跳过这篇文章，但开发环境可以预览——写一半的内容很安全。
- **SEO**：每篇文章自动生成 Open Graph / Twitter 卡片元数据；`rss.xml`、`sitemap.xml`、`robots.txt` 全部自动维护，RSS 还注册了自动发现，阅读器能直接找到它。
- **优雅降级**：浏览量统计基于 Vercel KV，没配置数据库时接口自动降级；评论区（giscus）没配置时整块隐藏。站点在"什么都没配"的情况下依然完整可用。
