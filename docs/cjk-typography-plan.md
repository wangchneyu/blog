# 中文正文排版方案

> 状态：已完成（2026-10-26）
> 范围：`--max-prose` 令牌 + `src/app/blog/[slug]/page.module.css` 的正文排版规则
> 前置：布局修复（`docs/layout-fix-plan.md`）与正文元素补全（`docs/prose-elements-plan.md`）已完成

---

## 一、问题

现有正文参数是照英文长文调的，没按中文重算。实测（1440px 视口）：

| 参数 | 当前值 | 问题 |
|---|---|---|
| 正文宽度 | 720px | 720 ÷ 16.8 ≈ **42.8 字/行**，中文舒适区是 32–38 字，读长段落时眼睛回扫距离过大 |
| 正文字号 | 1.05rem = 16.8px | 中文方块字比拉丁字母占面积大，16.8px 在高分屏上偏小 |
| 段落间距 | 1.5rem = 24px | 相对行高 31px 只有 0.77 行，段落切分感弱 |
| 标题行高 | **47.36px**（1.85，继承自正文） | h2 只有 25.6px，行高却是它的 1.85 倍，两行标题会散开 |
| 标题字距 | -0.02em | 负字距是为拉丁大写字母收紧设计的，中文汉字本身等宽，收紧只会显得拥挤 |
| 标题层级间距 | h2/h3/h4 统一 2.5rem | 三个层级没有间距差异，扫读时看不出结构深度 |
| 断行规则 | 默认 `auto` | 中文标点可能出现在行首（避头尾未开启） |

## 二、目标

在不改变站点视觉语言（渐变、玻璃卡片、令牌体系）的前提下，只调正文的**度**：

1. 每行落在 36–38 字
2. 段落切分一眼可辨
3. 标题层级靠字号 + 间距双重区分，行高不散
4. 中文标点遵守避头尾

## 三、明确不做

| 事项 | 原因 |
|---|---|
| 换字体（引入思源宋体等中文 Web 字体） | 中文字体动辄 3–8MB，子集化需要构建期工具链，收益与成本不成正比；系统字体已在各平台有合理解析 |
| 首行缩进 2 字符 | 与全站无缩进的现代风格冲突，且中英文混排时缩进宽度不齐 |
| `text-align: justify` | 中英混排 + 行内代码时会产生明显字距空洞，两端对齐在网页上弊大于利 |
| 全文居中或大留白改版 | 属视觉语言层，需对照页再定 |

## 四、方案

### P0-1 行宽与字号：720 → 660，16.8 → 17.6

```css
--max-prose: 660px;      /* 660 ÷ 17.6 ≈ 37.5 字/行，落进舒适区 */
.postContent { font-size: 1.1rem; line-height: 1.9; }
```

行高同步从 1.85 提到 1.9：字号变大后，同样倍率的绝对行距会自动增加，1.9 在 17.6px 下约 33px，接近中文长文常用的「字号 × 2」上限内的舒适值。

窄屏不做额外字号覆盖：390px 下正文 350px，350 ÷ 17.6 ≈ 19.9 字/行，与主流中文阅读类应用（约 20 字/行）一致。

### P0-2 段落间距与断行

- `p` 下边距 1.5rem → **1.75rem**（约 0.84 行），段落交界更清楚
- `text-wrap: pretty`：减少末行只剩一两个字
- `line-break: strict`：开启中文避头尾，禁止标点落在行首
- `text-spacing-trim: trim-start`：行首全角标点的多余空白收掉（Chromium 支持，其余浏览器忽略）
- `overflow-wrap: break-word`：长 URL 不再撑破容器

### P0-3 标题：修行高、拆层级、去负字距

```css
.postContent h1..h4 { line-height: 1.35; letter-spacing: normal; text-wrap: balance; }
h2 { font-size: 1.5rem;  margin-top: 3.5rem; }
h3 { font-size: 1.28rem; margin-top: 2.6rem; }
h4 { font-size: 1.1rem;  margin-top: 2rem;  }
```

三处变化各自解决一个具体问题：行高 1.35 让多行标题不再散；`letter-spacing: normal` 去掉对汉字无意义的负字距；间距按层级递减，形成 3.5 / 2.6 / 2 的节奏。

### P1 连带影响确认

`--max-prose` 被三处引用，需逐项确认收窄后仍成立：

| 引用处 | 影响 | 结论 |
|---|---|---|
| `.article`（文章页容器） | 页头、正文、上下篇、相关文章同宽 → 收窄后整页同步 | 保留单一对齐轴，正确 |
| TOC 侧栏 `left: calc(50% + var(--max-prose)/2 + 2rem)` | 自动跟随，间隙仍为 2rem | 无需改 |
| `.prose-container`（globals，未被任何页面使用） | 无 | 无影响 |
| blog / projects / about / 首页 | 用 `--max-content: 820px`，不引用 `--max-prose` | 完全不受影响 |

## 五、验收

| 项 | 标准 |
|---|---|
| 行宽 | 1440px 下正文 660px，字号 17.6px，行高 ≈33px |
| 标题 | h2 行高 ≈34.5px（1.35 × 25.6），非 47px |
| 移动端 | 390px 下 350px 正文，约 20 字/行，无横向溢出 |
| 视觉 | 明暗两主题截图对比，标题不散、段落有呼吸、无标点打头 |
| 工程 | `tsc` / `eslint` / `next build` 全部通过 |

## 六、回滚

改动为 `globals.css` 一行令牌 + `page.module.css` 若干属性，无依赖、无结构变更。回滚即还原这两个文件的对应段落。

## 七、实测结果（执行后回填）

用 CDP 读取 computed style，改动前后对照（1440px 视口）：

| 指标 | 改前 | 改后 | 目标 |
|---|---|---|---|
| 正文宽度 | 720px | **660px** | 660 |
| 正文字号 | 16.8px | **17.6px** | 17.6 |
| 行高 | 31.08px | **33.44px** | ≈33 |
| 每行上限 | 42.8 字 | **37.5 字** | 32–38 |
| 段落间距 | 24px | **28px** | 0.84 行 |
| h2 字号 | 25.6px | 24px | 1.5rem |

| h2 上间距 | 40px | 56px | 3.5rem |
| 标题字距 | -0.512px | **normal** | 汉字不收字距 |

### 一处计划外的连带修正

正文放大到 1.1rem 后，导语 `.postExcerpt` 的 1.15rem 与正文只差 0.05rem，视觉上已无层级差。已把导语抬到 **1.2rem**（19.2px），恢复约 1.1 倍的层级关系。这一项不在原方案内，属于改动的连带影响。

### 未做验证的部分

中文标点避头尾（`line-break: strict`）与 `text-spacing-trim` 的实际效果无法用截图断言，肉眼抽查未发现标点打头或异常空隙；`text-spacing-trim` 在 Firefox 不生效，属预期的渐进增强。

### 工程验证

`tsc --noEmit` 0 错误、`eslint` 0 错误 0 警告、`next build` 通过（13 个静态路由，样本文章仍未进产物）。
