# 个人主页改造方案：把「博客」变成「快速了解我」的入口

> 目标：任何访客打开首页，**10 秒内**能回答四个问题——你是谁、你在做什么、凭什么相信、怎么联系你。
> 状态：待执行 → 已完成

---

## 一、现状诊断：为什么现在做不到「快速了解」

用访客视角打开当前首页，实际读到的顺序是：

| 顺序 | 内容 | 访客得到的信息 |
|---|---|---|
| 1 | 「用代码探索智能的边界，用文字记录成长。」 | 一句文学标语，**没有主语** |
| 2 | 副标题第一句「Hi, 我是 wangc。目前就读于河北师范大学软件工程专业。」 | 终于知道是谁，但要读完才发现 |
| 3 | 副标题后半句堆了四件事：科研 / 全栈 / AI Agent / 数学建模 | 信息过载，没有主次 |
| 4 | 两个按钮：了解完整经历 / 阅读最新文章 | **没有项目，没有联系方式** |
| 5 | 领域两栏：多视图聚类 / 全栈开发 | 只是名词，没有证据 |
| 6 | 最新文章（1 条） | 站点看起来像刚建好 |

四个问题里，**第 3、4 个（证据、联系方式）在首屏完全缺失**；第 1、2 个（身份、方向）虽然存在，但被标语挡在后面、被四件事稀释。

另一处硬伤：`layout.tsx` 的站点描述写的是「专注于全栈开发、AI Agent 智能体以及数学建模」，与首页「我的主线是科研」互相矛盾。搜索结果和分享卡片展示的是另一个人。

### 根本原因

首页是按「有美感地介绍一个博客」设计的，不是按「高效介绍一个人」设计的。两者的差别是：

- 博客首页的默认读者是**回访者**，可以慢慢逛；
- 个人主页的默认读者是**第一次来的陌生人**（导师、面试官、合作方），只给一次机会。

后者要求**结论前置、证据可见、出口明确**。

## 二、信息架构改造

### 改前

```
HERO（标语 + 长副标题 + 两个泛按钮）
  ↓
领域（两栏名词）
  ↓
最新文章
```

### 改后

```
HERO ─────────────────────────────────
  小字身份行：河北师范大学 · 软件工程 · 2024—2028
  主标题：我是 wangc，做多视图聚类研究，也把 AI 做成产品。
  一句话定位（40 字内）
  证据锚点：ICLR 2027 在投 · IEEE VCIP 审稿人 · 6 个落地项目
  出口：查看项目（主） / 邮箱 / GitHub
  ↓
精选项目 / SELECTED WORK（3 张卡，读 projects.ts）
  ↓
科研与发表 / RESEARCH（方向 + 论文 + 审稿）
  ↓
最新文章 / WRITINGS（保留现状）
```

**删除**原「领域 / FOCUS」两栏：它提供的信息（两个方向名词）已被主标题和科研区完整覆盖，留着只是重复一次。

### 设计依据

| 决策 | 理由 |
|---|---|
| 主标题改写为第一人称陈述句 | `我是 X，做 Y，也做 Z` 是个人主页最高效的句式，一个逗号完成身份 + 两条主线 |
| 证据锚点做成三枚 pill 紧跟标题 | 陌生人判断"够不够格"靠事实不靠形容词；把最硬的三条（CCF-A 在投、国际会议审稿、项目数）提到视线第一落点 |
| 邮箱 / GitHub 放首屏 | 「快速了解」的终点是「能联系上」。现在要滚到页脚或翻到 about 最底部 |
| 精选项目上首页 | 本科生的说服力主要来自做出来的东西，不是描述 |
| 保留文章列表 | 它是长期价值，但从「首屏主角」降为「第三屏」——对陌生访客，文章是加分项不是入口 |

## 三、改动清单

### S1 · 新增 `src/lib/site.ts`（身份单一数据源）

现在姓名、邮箱、GitHub 散落在 `layout.tsx`、`Footer.tsx`、`about/page.tsx` 三处，改一次要动三个文件，且已经出现了不一致（描述文案与首页定位冲突）。

`site.ts` 导出：

```ts
export const site = {
  name, nameEn, affiliation, degree, period,
  tagline,          // 一句话定位
  email, github,
  proofs: [...],    // 证据锚点
};
```

`layout.tsx` 的 metadata、`page.tsx` 的 Hero、`Footer.tsx`、`about` 的联系区全部从这里取。

> **姓名说明**：站内目前统一使用 `wangc` 作为显示名，`site.ts` 里预留 `name` 字段，改成实名只需改一处。不擅自猜测中文姓名。

### S2 · Hero 重写（`src/app/page.tsx` + `page.module.css`）

- 新增 `.heroEyebrow`（身份小字）
- `.heroTitle` 文案替换，保留字号与移动端断点不动
- 新增 `.heroProof` / `.proofItem`（三枚证据 pill，移动端自动换行）
- `.heroCta` 改为：`查看项目`（主） + `邮箱` / `GitHub`（ghost）
- 删除 `.focusGrid` 区块及 `#focus` 锚点

### S3 · 首页新增「精选项目」区

读 `projects.ts` 中 `featured: true` 的条目（当前 3 个），渲染为两列卡片网格：

- 卡片：图标 + 标题 + 状态 + 角色 + 一句话 + 标签
- 有 `link` 时才出现「访问 ↗」
- 底部出口：「全部项目 →」指向 `/projects`

新增 `.projectGrid` / `.projectCard` 系列类，复用 `--radius-*`、`--bg-card`、`--border-color`，600px 下单列。

### S4 · 首页新增「科研与发表」区

- 左侧沿用原 `.focusBlock` 的渐变竖线样式展示「多视图聚类」大字（不浪费已有设计语言）
- 右侧两行事实：ICLR 2027 在投、IEEE VCIP 审稿人
- **不写论文标题**（在投阶段通常不宜公开），只写方向 + 会议 + 状态

### S5 · `/about` 项目区去重

`about/page.tsx` 手写了 4 个项目，与 `projects.ts` 重复。改为读 `projects.filter(p => p.featured)`，并附「查看全部项目 →」。

收益不只是去重：**以后新增项目只改 `projects.ts` 一处**。

### S6 · metadata 全站统一

| 字段 | 改前 | 改后 |
|---|---|---|
| title | `wangc \| 个人博客与作品集` | `wangc · 软件工程 / 多视图聚类` |
| description | 全栈开发、AI Agent、数学建模 | 学校 + 方向 + 证据 + 「欢迎交流」 |
| keywords | 缺「多视图聚类」 | 对齐科研主线 |

### S7 · Header / Footer 读 `site.ts`

页脚邮箱、GitHub 改为取 `site` 常量；导航不变（关于我 / 项目 / 文章三个入口已经够用）。

### 三处与方案不一致的地方

1. **首屏标题字号下调**。原 H1 是 `clamp(2.5rem, 5.5vw, 4.75rem)`，个人主页的陈述句比原来的短标语长得多（20+ 字），76px 下一行只放得下 11 字，必然折成三行且术语被拆。降到 `clamp(2.1rem, 4.6vw, 3.7rem)` 后稳定两行。视觉冲击略减，但「一眼读懂」优先于「一眼震撼」。

2. **新增 `.keepTogether` 类**。方案里没预见这一点：`text-wrap: balance` 会把「多视图聚类」拆成「多视图 / 聚类」，「AI Agent」拆成「AI / Agent」，专业术语被腰斩。给术语加 `white-space: nowrap` 后，桌面稳定断在逗号后，移动端三行但术语完整。

3. **about 项目区用「非竞赛组」而非 `featured`**。`featured` 里含「忆伴」，而 about 下方已有竞赛节，会造成同一项目出现两次。改为 `group !== "contest"`，正好还原 about 原本的 4 条工程类项目，只是文案改为从 `projects.ts` 取。

## 十、修订（2026-11-04）：首页收为一屏

原方案假设首页要承担「完整履历摘要」——精选项目、科研与发表、最新文章依次铺开。实际用下来这层是冗余的：三块内容在 `/projects`、`/about`、`/blog` 都有完整版本，首页再陈列一遍只是让访客多滚三次。

改动：

| 原首页内容 | 去向 |
|---|---|
| 「一手写论文，一手写代码。」 | 并入 `/about` 导语首句 |
| 三枚证据（ICLR / VCIP / 6 个落地项目） | `/about` 页头 pill，与导语同一视觉语言；打印版不出现 |
| 精选项目 ×3 | 删除（`/projects` 全量、`/about` 工程类 4 条） |
| 科研与发表 | 删除（`/about` 科研经历是同一内容的展开版） |
| 最新文章 ×3 | 删除（`/blog` 即列表） |
| 滚动提示 ↓ | 删除（下方已无内容） |

首屏出口由 3 个增至 4 个：查看项目 / 关于我 / 邮箱 / GitHub。移动端用 2×2 网格，避免 3+1 时最后一个独占一行。

高度改用 `100dvh`（`100vh` 作回退），移动端地址栏伸缩时仍是一屏。实测 1440×900：hero 836px（900 − 64 header），内容恰好一屏，页脚落在折线以下；390×844 无横向溢出。

`site.proofs` 随之从 `{label, href}` 改为 `string[]`——这组事实不再需要各自指向 `/about`（它本身就在 about 上了）。
